# KWVR Timetable

## Project context
- Timetable web app for the **Keighley & Worth Valley Railway** (KWVR).
- Structure is **airline-style**: a search box → a result table → links. The result table differs from an airline's (train services, stations, heritage-railway specifics) — follow the Figma design, not airline conventions, where they diverge.
- Data comes from a **single external API**. The API itself is **out of scope** — we only consume it.
- Data flow: `TimetableSearchForm` emits `search` (criteria) → the page writes it to the URL (`/?from=haworth&date=2026-10-12&time=14:30`, a pushed history entry, so a search can be shared and Back goes to the previous one; see "Shared links") and hands it to `useTimetableSearch` (owns the page state) → `GET /api/timetable/search` (our Nuxt server endpoint) → `fetchTimetableByQuery` (`server/utils/timetableApi.ts`) → the external API. If the external API fails, the endpoint logs its error and fails too, with a 502 (its details never reach the browser), so the page shows the error state; a request with no answer after 15s (`SEARCH_REQUEST_TIMEOUT_MS`) fails the same way. The endpoint still holds every answer 500ms (`SKELETON_CHECK_DELAY_MS`, TEMPORARY, kept on purpose until the real back end exists). The external API doesn't exist yet, so `fetchTimetableByQuery` returns a dummy response (and `SIMULATE_TIMETABLE_API_ERROR`, TEMPORARY, makes it fail on purpose), a whole timetable (`server/data/dummy-timetable-response.json`, the orange one: each call has a `time` and a `timeType` (`departure` / `arrival`), and trains and stations carry `notes` codes resolved through the `key`; typed by `TimetableApiResponse` in `app/types/timetableApi.ts`), and `getTrainServicesByCriteria` (`app/utils/timetableResponse.ts`) picks the trains leaving the searched station at or after the searched time, both ways, as result rows, each with its symbols (`notes`: the train's, then those of the stations it calls at from the origin on).
- The back end's contract is `public/timetable-api-contract.json` (OpenAPI 3.1: `GET /v1/timetable?originId=haworth&departingAfter=2026-10-12T14:30`, the response's JSON Schema, the rules a schema can't express, errors, examples). It is the source of truth for `TimetableApiResponse`: change both together. The dummy response validates against it.
- Must be **fast on desktop and mobile**.
- **Accessibility first** — it is a requirement, not an afterthought.
- **Unit tests only** (no e2e).
- Design lives in **Figma**: https://www.figma.com/design/6OXQWKSVSEQqa4RcylfEZv (desktop + mobile, each with an empty state).
- Links (nav, legal, social, contact) mirror the official site https://kwvr.co.uk.
- Hosted on **Netlify** (server-rendered), see "Deploy (Netlify)". Agents get the site as Markdown, see "Agents (AEO)".

## Brand (KWVR Brand Guidelines)
- Palette: Burgundy `#a32638`, Cream `#f4f4e9`, Grey `#423d33`, White `#ffffff`, plus the pastel `#f3e4e6` (burgundy tint). Defined once in `app/assets/css/tokens.css`.
- Text is grey or white. Burgundy is the accent (headers, buttons, stand-out text). Cream is for backgrounds only.
- Exception: the main nav links are black (`--colour-text-nav`) with no underline, per Figma.
- Exception: form errors use a red outside the palette (`--colour-red` #c00000, via `--colour-text-error` / `--colour-border-error`), at 14px (`--font-size-xs`).
- Pastel shades tell timetables apart (e.g. the tint marks alert rows and the last train's row).
- Font: Gill Sans, from a local font stack only (no webfont files). SemiBold for headers, Regular for body.
- Left-align long text; centre only short snippets.
- **No icons yet** — they're still being confirmed. Use text labels (e.g. "Service alert") until the icon set is approved. Exceptions: built-in control affordances (the Select's chevron and ✓) and the footer social links, which use brand logos from Simple Icons (`@iconify-json/simple-icons`, CC0, bundled locally) with a visually hidden text name, and the timetable key symbols (diesel, steam, bar, National Rail, Rail Story) from kwvr.co.uk's printed timetables, plus our own last-train symbol (a clock on 11:00, drawn in the same black-glyph style, as the printed key has none), in `public/images/timetable-key/` as 96px WebP. Their paths, alt text (`label`) and meanings (`description`) come from the API response's `key`, never hard-coded. On hover a symbol shows its `label` in a tooltip (`TimetableNoteIcon`: `UPopover` in hover mode, the tooltip text `aria-hidden` because the alt text already says it).
- Footer legal links have no underline (they sit in a labelled `<nav>`); they underline on hover like the main nav.
- Footer social logos grow to 1.1 on hover (pointer devices only, a `transform` transition), like the timetable symbols.
- Footer social links open in a new tab (`target="_blank"`, `rel="noopener noreferrer"`), with "(opens in a new tab)" in their visually hidden name.
- The header logo links to this app's home (`homeHref: '/'`), as a plain `<a>` on purpose: a full load of `/` starts over (clears the search state, leaves the error page).
- The logo is the "Worth Valley" totem sign: `public/images/logo.png`, the user's compressed 133×38 PNG (6 KB; the old `logo.svg` was a 331 KB embedded raster). The favicon (`public/favicon.ico`, 16/32/48px, transparent), the home screen icon (`public/apple-touch-icon.png`, 180px on cream) and the link preview image (`public/images/og-image.png`, 1200×630 on cream) were made with Pillow from the same sign's 4096×1166 original, a base64 PNG inside the old `public/images/logo.svg` (in git history, e.g. commit 2359427): to remake them, extract it from there and fit it to each canvas's width (favicon), 156px (touch icon) or 840px (preview), centred.

## Stack
- Nuxt 4 (`app/` directory layout), Vue 3, TypeScript (strict)
- pnpm (`packageManager` pinned in `package.json`) — never use npm/yarn
- VueUse (`@vueuse/nuxt`, composables auto-imported)
- GSAP (client-only plugin, out of the entry bundle: `plugins/gsap.client.ts` starts its download at app start, in parallel with hydration, and provides `$loadGsap()`; use `const $gsap = await useNuxtApp().$loadGsap()` in `onMounted`, calling `useNuxtApp()` before the await, and skip the work if the component unmounted meanwhile)
- Plain CSS with custom properties — no preprocessors, no utility classes in our code
- Nuxt UI v4 (`@nuxt/ui`) for interactive components (`USelect`, `UButton`, …). Tailwind CSS v4 is installed only as Nuxt UI's styling engine. `ui.fonts` and `ui.colorMode` are off (local fonts only, no dark mode). Icons come from locally bundled sets only (`@iconify-json/lucide` for control icons, `@iconify-json/simple-icons` for social logos), with `icon.fallbackToApi: false`, so nothing is fetched from the Iconify API
- The site is boxed at 80rem with Nuxt UI's `UContainer` (`--ui-container` ← `--layout-max-width` in tokens.css): `SiteFrame` (used by `app.vue` and `error.vue`) wraps header, main and footer in a `UContainer` (`.site-frame`, no gutter, so the bands' backgrounds stop at the box edge), and every content column (header, footer bands, page sections) is a `UContainer` too, with its gutters (1rem / 1.5rem from 40rem / 2rem from 64rem). Give it `as="section"` (or `header`) and keep the element's own class; there is no `.container` class. Set only `padding-block` on a `UContainer`, so its gutters stay in place.
- ESLint via `@nuxt/eslint` with stylistic formatting (no Prettier) + `eslint-plugin-vuejs-accessibility`
- Vitest + `@nuxt/test-utils` + happy-dom + `vitest-axe`
- `@nuxt/image` for responsive images: `useImage()` builds resized/cropped WebP URLs (ipx locally). Keep srcset widths at or below the original's width, and keep originals in WebP
- `@internationalized/date` (Nuxt UI's optional peer) for `UCalendar`/`UInputTime` values (`CalendarDate`, `Time`)
- TypeScript is pinned to `~6.0` because typescript-eslint doesn't support TS 7 yet
- `nuxt.config.ts` has a `nitro.externals.inline` workaround for a Nuxt 4.6.0 Windows SSR bug ([nuxt#36467](https://github.com/nuxt/nuxt/issues/36467)) — remove once a Nitro release includes nitrojs/nitro#4732

## Page states
The content area under the search box shows exactly one state, driven by `TimetableSearchState` (`app/types/timetable.ts`) through a `v-if` / `v-else-if` chain in `pages/index.vue`. The chain sits in `.timetable-page-content`, which fills down to the footer on a short page and is at least one screen tall (`.is-screen-tall`: `min-height: 100vh` then `100svh`) while loading (or checking a link) and with results only, so swapping states (the tall bento for the shorter skeleton) never pulls the footer up into view. First use, no results and error take their natural height (the short illustrated states would otherwise leave a big empty band above the footer). Nothing scrolls after a card click. The states only a search reaches (results, no results, error) are `Lazy…` components: their own chunks, prefetched once the page is idle, so the first visit doesn't download the results' table, modal, map and message states up front; first use and loading stay eager (they're on the first paint).

| Status | Component | When | Current status |
|---|---|---|---|
| `first-use` | `TimetableFirstUseState` | No search yet (Figma's "empty state"): "Or catch the next train from…" + `StationBento` | Done |
| `checking-link` | `TimetableLoadingState` | A search in the URL (a shared link), from the first paint (SSR too) until the form checks it in the browser (it reads the user's clock) and sends it or refuses it | Same branch as `loading` (no remount when it's sent) |
| `loading` | `TimetableLoadingState` | Search sent, waiting for the API | Skeleton (UTable) + Key placeholder |
| `results` | `TimetableResultsState` | API returned services | `TimetableResults` (a UTable, services from the dummy response; rows open the journey modal) + `TimetableResultsKey` + `StationInfo` (the searched station, with a click-to-load OpenStreetMap map) + `StationSuggestions` (three other stations at random) |
| `no-results` | `TimetableNoResultsState` | API returned nothing | Station-clock illustration, message, "Take me home please" button |
| `error` | `TimetableErrorState` | The request failed | Derailed-train illustration, message, "Take me home please" button |

- First use: `StationBento` is Vue Bits' [MagicBento](https://vue-bits.dev/components/magic-bento) layout with every effect off (plain CSS; only the 2px hover lift is left, on the `translate` property because GSAP owns the card's `transform`). Each card is a stretched `<button>` inside an `<h3>`; choosing one calls the search form's exposed `searchNextTrainFromStation`, so the form shows the station, date and time searched (the next departure, by the prefill rule). Card photos sit under a scrim (`--colour-photo-scrim*`): white text only where it's at least 55% black.
- Bento entrance: `useStationBentoEntranceMotion` brings the cards in one after another, each fading in from 64px outside its place, straight out from the bento's centre (so they converge at 4, 2 and 1 columns; measured before tweening). GSAP `fromTo` (opacity 0 → 1, 0.6s, `power3.out`, 0.08s stagger, `clearProps: 'transform,opacity'`) under `(prefers-reduced-motion: no-preference)` only. `fromTo`, not `from`: an anti-flash guard (`station-bento-entrance-pending` on the list, `opacity: 0` on the cards under no-preference, with a 2s CSS reveal in case the script never runs) keeps the server-rendered cards hidden, and `from` would read its 0 as the end value. The composable returns `isBentoEntrancePending`, set to false at the end of `onMounted`, once GSAP has loaded and hidden the cards (or once it has loaded, under reduced motion). If the 2s CSS reveal has already shown the cards (a slow phone, or GSAP slow to load), the entrance is skipped rather than hiding them again (`areCardsAlreadyRevealed`: every card's computed opacity is 1). `.first-use-state` has `overflow-x: clip`, so cards starting outside never scroll the page sideways.
- Loading: a visually hidden "Departures" `<h2>` (the results' heading) and "Loading departures…", plus `TimetableResultsSkeleton` and `TimetableResultsKeySkeleton` (the Key under the results: a heading bar and three symbol lines), so nothing jumps when results arrive. The table skeleton uses the results table's own classes (`timetable-table timetable-table-departures`, `departure-*` cells, `timetable-table-row`), so it can't drift from it; only its bar shapes are its own. Both are `UTable`/`USkeleton` and `aria-hidden` (USkeleton marks each block `role="alert"`). The section's padding and the Key placeholder's top margin match the results' and the Key's spacing.
- Results: `TimetableResults` is a `UTable` (user's choice) with a screen-reader `caption` and `<th scope="col">` headers; cells are drawn by `#<column>-cell` slots (with `TimetableResultStationTime` and `TimetableResultInfo`), backgrounds, dividers and the outer rounded corners sit on the cells (a row can't take a radius), row classes (e.g. `has-service-alert`) go through the table's `meta.class.tr`. The table's look (`.timetable-table*` classes) lives in the non-scoped `assets/css/timetable-table.css`, shared with the journey's stops; the departures layout (column widths, `departure-*` cell alignment, the mobile card layout) is there too, under `.timetable-table-departures`, shared with the skeleton (its mobile overrides come after the base corner and divider rules, at least as specific). Only the row hover, the row's containing block and the icons' z-index stay scoped in `TimetableResults`, whose section wraps a `UContainer` (the section stays the element GSAP and the click hand-off use). UTable's body cells are always `<td>`, so the origin is not a row header. The mobile cards change the table parts' `display`, and Safari then drops their table semantics, so `useExplicitTableRoles` writes each part's role on it in `onMounted` (`table`, `rowgroup`, `row`, `columnheader`, `cell`: UTable takes no attributes for its parts; its rows don't change after mount).
- Journey: each row is clickable through `TimetableResultJourneyButton`, a stretched `<button aria-haspopup="dialog">` in the origin cell (visually hidden "Journey details: Haworth 10:22 to Keighley 10:43"; its `::after` covers the row, the row is `position: relative`, and the focus ring sits inset on the `::after`). Not UTable's `@select`: that makes each `<tr tabindex="0">` with no role. On hover the row's cells take a darker background (`--colour-surface-alt-hover` / `--colour-surface-alert-hover`), the text untouched and no colour transition; never opacity on the cells (it would stack them above the hit area). The symbol icons sit above the hit area (`z-index: 1`) so their tooltips work; a click on one is handed to the row's button in script. The button opens `TimetableJourneyModal` (`UModal`, `scrollable`: the overlay scrolls the whole modal on short screens; the table is never clipped into its own scroll box): title "Haworth to Keighley", description "Departs … · 4 stops", a stops `UTable` (Station / Time, same classes as the results) from the boarding station to the end of the line (each result carries `calls`, with a "Request stop" text tag from the key's `x` and the station's symbols), then "About this journey" (only that train's symbols, plus the request-stop wording with its tag stacked above it). `TimetableResults` keeps the selected service after close (no empty leave transition) and returns focus to the row's button via `content.onCloseAutoFocus` (Safari doesn't focus buttons on click).
- Entrance: `useResultRowsEntranceMotion` slides the body rows up into place (one GSAP timeline, two `from` tweens at position 0: y 32 and scale 0.95 (coming from the back), 0.25s, `sine.in`, 0.025s stagger, `clearProps: 'transform'`; the user's own values), with a subtle fade alongside (opacity 0, 0.15s, same ease and stagger, `clearProps: 'opacity'`: shorter than the rise, so the rise from below still shows; on the rows, never the cells) under `(prefers-reduced-motion: no-preference)` only. Never put a CSS `transition` on a property GSAP animates (it lags every frame); it replays on each new result set because the results state remounts `TimetableResults`.
- Last train: `getTrainServicesByCriteria` marks only the latest departure from the searched station, whichever way it goes, `isLastTrain` (one per search, always the last row; the user's call, it used to be one each way) and puts the key's `last-train` symbol first in its `notes` (the response doesn't mark it; the symbol's path, label and wording come from the key). Its row gets `is-last-train` (`--colour-surface-last-train`, the burgundy tint for now, and a darker shade on hover, `--colour-surface-last-train-hover`); an alert's tint wins on a row that is both. The symbol keeps it from being colour alone; the row's button adds ", last train" and the modal's description "· Last train". The Key and "About this journey" list it like any symbol.
- Trains to Keighley: their rows are a shade darker than the cream (`is-to-keighley`, set in `TimetableResults`'s `meta.class.tr` from the destination's id; `--colour-surface-to-keighley`, cream with 6% grey, and `--colour-surface-to-keighley-hover`, 16%, on hover), so the two ways down the line tell apart in the one table (the user's choice, after a table per destination was tried and dropped). The Destination column keeps it from being colour alone. The last train's and an alert's tints win on a row that is also to Keighley (their rules come after it).
- Day hint: when the search is for a day other than today, `TimetableResultsDayHint` puts "* These trains are not for today" (14px, `--font-size-xs`, the asterisk `aria-hidden`) above the table, in the results and in the loading state (so the table doesn't shift when results replace the skeleton). Today is read from the user's clock in `onMounted` (`isDepartingAfterOnDate`), so the hint can only appear after mount: its line (`.results-day-hint-line`, one 14px line plus its margin) is always there, empty for today, so it never pushes the table (or a shared link's server-rendered skeleton) down.
- Symbols: the Info cell shows each result's `notes` as 24px icons whose alt text is the note's `label`, except a line end's station symbols (National Rail connections at Keighley; `LINE_END_STATION_IDS` in `TimetableResults`, read from the first and last `calls`), which sit beside that station's name in the origin or destination cell (`TimetableResultStationTime`'s `notes`); the service's `notes` stay whole, so the Key and the journey modal are unchanged; `TimetableResultsKey` (under the table, in `TimetableResultsState`) lists the symbols those results use, each once, with the key's `description` and a decorative icon (`alt=""`), through `TimetableNoteList` (also used by the journey modal). The skeleton's info cell has a placeholder for the icon row.
- Station info: after the Key, `TimetableResultsState` shows `StationInfo` for the searched station (from `data/stationDetails.ts`, matched by id): an `<h2>` "Haworth Station", our description, and, only when the station page lists any (Damems has none), an `<h3>` "Things to do" with a list of their titles. Beside it (above it on mobile, by `order`; the map box holds the section's only focusable things, so focus order holds), the map box (5:3, cream, bordered), **click to load**: it first shows "The map comes from OpenStreetMap, an outside site.", a "Show map" `UButton` (visually hidden " of Haworth station") and an "Open in OpenStreetMap" link (new tab, `openstreetmap.org/?mlat=<lat>&mlon=<lng>#map=16/<lat>/<lng>`). The button swaps in the `<iframe>` (OpenStreetMap's embed, `openstreetmap.org/export/embed.html?bbox=<box>&layer=mapnik&marker=<lat>,<lng>`, the box ±0.006° longitude and ±0.0025° latitude round the station (about 800×550m), rounded to 4 decimals; coordinates from Wikipedia; `title="Map of Haworth station"`; `referrerpolicy="strict-origin-when-cross-origin"`, so the search in our URL never reaches OpenStreetMap) and moves focus into it. So nothing reaches another site (scripts, tiles, the referrer) without the user asking, and OSM's tile servers (whose usage policy asks for restraint) only serve maps someone looks at. Both URLs come from `utils/stationMapLinks.ts`. The box grows past 5:3 on the narrowest phones rather than clip the placeholder.
- Station suggestions: then `StationSuggestions`, three `StationSuggestionCard`s (`<li>` roots) under a small visible `<h2>` "More stations to explore" (`--font-size-lg`, centred over the cards), picked by `pickRandomStationHighlights` (`utils/stationSuggestions.ts`: drops the searched station, then a Fisher–Yates pick on a copy; `getRandomNumber` injectable for tests). Random in setup is safe because the results state never renders on the server, and it reshuffles on each search because the state remounts after loading. Each card (cream, portrait photo cropped 3:4 by `useImage()` at 240–600w, so no crop is taller than the shortest original) holds an `<h3>` with a stretched `<a target="_blank" rel="noopener noreferrer">` to the station's page on kwvr.co.uk (`pageHref` in `stationHighlights.ts`), "Haworth station" plus a visually hidden "(opens in a new tab)", described by the card's line. The focus ring goes round the whole card (on the link's `::after`); hover (pointer devices) is the bento card's 2px `translate` lift and faded-in shadow.
- Error and no results share `TimetableIllustratedState` (props: heading, message, illustration src/size/`sizes`): a decorative illustration (`alt=""`, `useImage()` srcset up to its original's width), an `<h2>` labelling the section, a short paragraph and a "Take me home please" `UButton` (`.button-primary`, the 404's wording), centred on the cream band like the first-use state. Each state sets its illustration's display width with `--illustrated-state-image-max-width` in its own scoped style. The button is a button, not a link (we're already on `/`): it emits `return-home`, and the page (`returnHomeToStationCards`) calls `resetTimetableSearch()` (back to first use), clears the URL's query (`navigateTo({ query: {} })`), then calls the form's exposed `focusSearchForm` (focus on the station field, as the button is gone). The illustrations' white was made transparent by colour-to-alpha (`alpha = 255 − min(R,G,B)`, black colour, alpha under 12 cleared), so their light-grey fills tint with the band.
- Error: `TimetableErrorState` is the derailed train (portrait, 16rem / 20rem from 40rem), "Sorry, we couldn’t load the timetable" and a "try again" paragraph. The live region says "Sorry, we couldn’t load the timetable." It shows only when the endpoint fails (an external API failure → our 502); to see it in dev, set `SIMULATE_TIMETABLE_API_ERROR` in `server/utils/timetableApi.ts`.
- No results (not an error: the search worked, but no train runs that day or after that time): `TimetableNoResultsState` is the station clock over an empty platform (landscape, 20rem / 30rem from 40rem; the scene runs to the frame, so its edges are feathered into the band), "Sorry, there are no trains at that time" and "try another date or an earlier time". The live region says "Sorry, there are no trains at that time." It shows only when the search worked but found no trains (the endpoint answered with no services); to see it in dev, search after the dummy timetable’s last train (e.g. 18:00).
- Latest search wins: `useTimetableSearch` only writes an outcome if the state is still loading with the same criteria object (`searchState` is a `shallowRef`, so that's the raw object, not a proxy).
- Same search, no new call: `useTimetableSearch` skips a search with the same station and `departingAfter` as the one loading or shown (`isSearchOnScreen`: `loading`, `results` or `no-results` with equal criteria, by `isSameSearchCriteria`); after an error it runs again, as the retry, and a link's search still `checking-link` does go out. The page pushes the URL only when it doesn't already hold an equal search.
- Shared links: the search lives in the URL (`utils/searchRouteQuery.ts`: `getRouteQueryBySearchCriteria` and `getSearchCriteriaByRouteQuery`, which needs a known station and a real date and time, `parseDate` / `parseTime`, else `undefined`; no clock, so safe during SSR). A query-only change neither scrolls nor remounts the page.
  - On load, `pages/index.vue` passes the URL's search to `useTimetableSearch(linkedCriteria)`, which starts on `checking-link`; its `onMounted` (after the form's prefill) calls the form's exposed `searchFromAddressBar`, which fills the three fields (`getSearchFormValuesByCriteria`) and runs `submitSearch` (same checks, errors and focus move as Search; resolves to whether a search went out).
  - A stale link (a past day, or a time already gone today) is refused like the form: the form shows the link's values with its usual errors, nothing is sent, and the page goes to first use (station cards). The URL is kept, since it matches the form.
  - Back/Forward: a `watch` on the URL's search runs it through `searchFromAddressBar` unless it's already on screen (our own push lands with its search loading); no search in the URL → first use.
  - A refused time must never be "fixed" behind its error: the date picker's clamp (`commitDepartingDate` in `useDepartureTimeLimit`) runs on its own `@update:model-value` (a user's pick), not on a watcher, so a date set in code never moves the time.
- Substates belong in their variant of the union (e.g. an error `kind`), not in extra flags.
- The `aria-live="polite"` summary (`.results-summary`) stays rendered in every state. Its text comes from the state: empty on first use, "Searching for departures from Haworth…" while loading (and while checking a link), the count with results.

## Error page
- `app/error.vue` handles every error (Nuxt renders it instead of `app.vue`, hence the shared `SiteFrame`). It copies kwvr.co.uk's 404 structure (e.g. https://kwvr.co.uk/esdsa): a section with a `<header>` + `<h1>` "Oops! That page can’t be found.", the paragraph "It looks like nothing was found at this location." (their "Maybe try a search?" dropped) and, instead of their search form, a "Take me home please" `UButton` (`.button-primary`). Other errors get "Sorry, something went wrong." / "Please try again in a moment.". Title: "Page not found — Keighley & Worth Valley Railway".
- The button is a real link (`to="/"`, works before hydration, opens a tab on middle/modifier click); a plain click calls `clearError({ redirect: '/' })` instead, because a router push to the route the error happened on wouldn't clear it.

## SEO
- The absolute site URL is `runtimeConfig.public.siteUrl`: `NUXT_PUBLIC_SITE_URL`, else Netlify's `URL` (the primary domain, at build), else `http://localhost:3000`. It feeds the canonical link, link previews, JSON-LD, robots.txt, the sitemap and llms.txt.
- The site's name, title, description (~150 characters, naming the six stations) and one-line summary live in `data/siteContent.ts`, shared by `nuxt.config.ts` (the default head), the page and the server.
- `useTimetablePageSeo` (called by `pages/index.vue`) sets the page's head: a search link gets its own title and description ("Trains from Haworth after 10:00 on 13 October 2026 — …", no clock involved, so server and browser agree), so a shared link previews as that search and each history entry is named. Open Graph + X (`twitter:card` `summary_large_image`, `twitter:site` `@WorthValley`, `twitter:image:alt` = `og:image:alt`, `og-image.png`, `og:url` = the address shown, `og:locale` `en_GB`); `<link rel="canonical">` always the home page (every search link is that page to search engines); `<link rel="alternate" type="text/markdown">` to `/index.md` with the same search; JSON-LD `@graph` with the railway's `Organization` (from `siteLinks`: legal name, phone, email, social profiles; logo = the 180px touch icon) and the `WebSite`.
- The global head (`nuxt.config.ts`): favicon, apple-touch-icon, `theme-color` (the brand burgundy, written as hex: CSS variables can't reach the head), and a `text/plain` alternate link to `/llms.txt`.
- `robots.txt` welcomes every crawler (AI ones included), disallows `/api/`, and points to `sitemap.xml`, which lists `/` only.

## Agents (AEO)
- Every page and search is available as Markdown, built on the server from the same content and the same API call and rows as the page (so they can't drift): `server/utils/siteMarkdown.ts` (the home page: how to search and link to a search with its pattern `/?from=<station-id>&date=<YYYY-MM-DD>&time=<HH:MM>`, the station ids, each station's description, things to do, map link and kwvr.co.uk page, the visiting links and the contact details) and `server/utils/departuresMarkdown.ts` (a search's trains as a table with stop counts and notes, each train's stops with request stops, the key's meanings; or the no-results / error wording).
- `/index.md` (not prerendered: its query matters): the home page, or with a search query (`/index.md?from=haworth&date=2026-10-13&time=10:00`) that search's departures, via `getIndexMarkdownByQuery` (`server/utils/indexMarkdown.ts`: the page's own `getSearchCriteriaByRouteQuery` and `getTrainServicesByCriteria`; a query that doesn't hold up gets the home page; an API failure is a 502; no clock, so a past day still answers). Its `Link: <…/>; rel="canonical"` header (routeRules) sends search engines to the HTML.
- `/` for agents: `server/middleware/markdownForAgents.ts` answers `GET /` (and `/?from=…`) with the same Markdown when the client prefers `text/markdown` (Accept) or is a known AI assistant or crawler (`server/utils/agentDetection.ts`, from the `website` project; Googlebot and Bingbot get the HTML), and adds `Vary: Accept, User-Agent` to every `/` response.
- `/llms.txt` (llmstxt.org: name, summary, links to the Markdown, the stations with their ids) and `/llms-full.txt` (the home page's Markdown: the site is one page) are prerendered with robots.txt and sitemap.xml (`nitro.prerender.routes`), served as static files. Every response carries `Link: </llms.txt>; rel="llms-txt"` (routeRules).
- The server imports app code (`~/data/…`, `~/utils/…`): Nitro gets Nuxt's aliases. Keep those files free of app-only auto-imports (they import what they use), and keep the server builders' imports explicit too, so the specs can load them.

## Deploy (Netlify)
- `netlify.toml`: `pnpm build`, publish `dist/`, Node 24. Nitro picks its `netlify` preset by itself on Netlify's build (the pages, `/api` and `/index.md` run as one Netlify Function; static files from `dist/`), and `@nuxt/image` switches to Netlify Image CDN by itself. Only static-file caching is set there: `/_nuxt/*` immutable for a year, `/images/*` a week then revalidated.
- Response headers live in `nuxt.config.ts` `routeRules`: Nitro sends them from the function and writes them into `dist/_headers` for the static files, so one list covers every response. In production only (`$production`): HSTS, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `X-Frame-Options: DENY`, and a **report-only** CSP (`'unsafe-inline'` scripts for Nuxt's inline config script, `frame-src https://www.openstreetmap.org` for the station map). Check the browser console on a deploy preview for violations, then rename it to `Content-Security-Policy`.

## Coding rules
- Arrow functions everywhere (`func-style: expression`, `prefer-arrow-callback`).
- PascalCase for components (files and template usage).
- Descriptive names — no generic `getData`/`getUser`; prefer `getServicesByStation`, `formatDepartureTime`.
- Split any file over 250 lines (`max-lines` warns).
- No `any`; use `import type` for type-only imports.
- Style with CSS custom properties from `tokens.css` — never hard-code colours in components.
- Plain CSS; no utility classes in our code. Theme Nuxt UI via `--ui-*` in tokens.css; restyle a Nuxt UI component by giving it an unlayered class (via `class` or `:ui` slot hooks). Unlayered CSS beats Nuxt UI's layered utilities whatever the specificity.
- Scoped styles don't reach inside multi-root Nuxt UI components (e.g. `USelect`, `UButton`): target their classes with `:deep()` under a scoped ancestor, and use a non-scoped `<style>` for portalled content (menus).
- No `console.log` (only `console.warn` / `console.error`).

## Accessibility rules (WCAG 2.2 AA)
- Result tables use semantic markup: `<table>`, `<caption>`, `<thead>`/`<tbody>`, `<th scope="col">` (and `<th scope="row">` where the markup is ours; the results are a UTable, see Page states). No div-tables.
- Every form control has a visible `<label>`; group related inputs with `<fieldset>`/`<legend>`.
- Full keyboard operability; logical tab order; never remove focus outlines (use `:focus-visible`). One exception: the station menu's options (`TimetableOriginSelect`) show focus as the highlighted option's solid burgundy pill with white text (~7.6:1), not the ring (reka moves focus to an option in script, and after a load Chrome drew our ring round it as if by keyboard); under forced colours the highlighted option gets a `Highlight` outline.
- Colour contrast ≥ 4.5:1 for body text, ≥ 3:1 for large text and UI components. Never convey meaning by colour alone. The disabled grey (`--colour-text-disabled`, 3.4:1) is for disabled controls only (e.g. the calendar's past days), never for a value still being edited (a time already gone keeps the normal text colour, struck through).
- Nothing may cover the focused element (2.4.11): the mobile menu closes when focus moves out of it (`focusout` with a next target outside the `<nav>`; leaving the window keeps it open), besides Esc and a click outside.
- Form errors appear only after a search is tried, under the field to fix, tied to its control with `aria-describedby` (plus `aria-invalid` where the role supports it), with a visually hidden "Error:" prefix; focus moves to the first field to fix. Never disable the submit button.
- Announce async results (e.g. search results count) via an `aria-live="polite"` region.
- Touch targets ≥ 24×24 CSS px (WCAG 2.2 2.5.8).
- Use `.visually-hidden` for screen-reader-only text.
- `lang="en-GB"` is set globally; times/dates use `<time datetime="…">`.
- Anything read from the user's clock (e.g. the search form's date/time prefill) is set in `onMounted`, never during SSR — the server's clock and time zone differ and would break hydration.

## Motion
- All GSAP animations must honour `prefers-reduced-motion`: wrap them in `$gsap.matchMedia()` (or check VueUse's `usePreferredReducedMotion()`), and provide a no-motion path.
- GSAP loads asynchronously (`await useNuxtApp().$loadGsap()`, see Stack): until it's there, the menu opens and closes instantly, and anything an entrance hides must have a CSS fallback (like the bento's 2s reveal).
- Animate transforms/opacity only; never block content behind an animation.
- `main.css` also has a global CSS reduced-motion guard.

## Testing
- Unit tests only, in `test/unit/**/*.spec.ts`.
- Use `mountSuspended` from `@nuxt/test-utils/runtime` for components needing Nuxt context.
- Add an axe assertion to component specs: `expect(await axe(wrapper.html())).toHaveNoViolations()`.
- The server's Markdown and crawler builders are pure functions, specced in `test/unit/server/` (imported by relative path).
- Mock the external API — tests never hit the network. `vitest.config.ts` sets happy-dom's `disableIframePageLoading`, so an iframe (StationInfo's map) never loads its page, even once vitest-axe puts it in the document. Mock our endpoint with `registerEndpoint` (`@nuxt/test-utils/runtime`); registrations for one URL pile up and the latest wins, so use `once: true` or call the returned unregister function (once only).
